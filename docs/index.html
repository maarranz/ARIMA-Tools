Overview and purpose

ARIMA-Tools was developed for the Applied Time Series Econometrics (ATSE) course at Universidad Carlos III de Madrid. It complements Statsmodels and StatsForecast with teaching-oriented tables, summaries, numerical forecasts, and interactive Plotly figures.

This document describes the software/API. The ATSE course material provides the econometric theory; the Labs provide fuller worked examples and exercises. The package currently exposes 30 public functions through a deliberately flat API: use import arima_tools as at and call at.function(...). Internal modules organize the implementation; users do not need submodule imports.

Diagnostics have three layers: parameters and model structure, residual behavior, and model behavior (dynamics and parameter stability). These concepts overlap the implementation modules.

Installation, environment, and import

For Google Colab, the target installation command is:

%pip -q install "ARIMA-Tools @ git+https://github.com/maarranz/ARIMA-Tools.git@v1.0.1"

Then use import arima_tools as at; pip supplies the runtime dependencies. The v1.0.1 tag will be published after release validation; until then, replace v1.0.1 with the packaging commit SHA.

For repository files and development, clone the repository and recreate the mamba environment only if needed, from its root:

mamba env create -f environment.yml
mamba activate atse_arma_tools

environment.yml specifies Python 3.14 and the full notebook/test environment. Activate an existing environment without recreating it. Source-tree imports require running from the repository root; an installed package can be imported from other directories. The following imports apply to either workflow:

import numpy as np
import pandas as pd
from statsmodels.tsa.arima.model import ARIMA
from statsmodels.tsa.arima_process import ArmaProcess
import arima_tools as at

Small example used below

The explicit data-generating process is a zero-mean ARMA(1,1): y[t] = 0.7*y[t-1] + eps[t] + 0.4*eps[t-1], with independent standard-normal innovations (variance 1). The fixed seed, 100-observation burn-in, and 240 retained observations keep the example reproducible and small. Monthly dates are illustrative labels for this simulated series.

rng = np.random.default_rng(12345)
process = ArmaProcess(ar=[1, -0.7], ma=[1, 0.4])
y = pd.Series(
    process.generate_sample(nsample=240, burnin=100, distrvs=rng.standard_normal),
    index=pd.date_range("2000-01-01", periods=240, freq="MS"),
    name="y",
)
arma_y = y.copy()  # Keep this example for the later stability section.
result = ARIMA(y, order=(1, 0, 1), trend="n").fit()

Run the Python blocks below in sequence in the same fresh session. The early examples use this y and result; the intervention example defines its own data and results, and the stability example explicitly returns to the original ARMA fit. Functions accepting results or result normally expect a fitted Statsmodels ARIMA result. Exceptions, such as AutoARIMA summaries and plots of recursive tables, are identified below. Tables are pandas objects; plotting functions return Plotly Figure objects. In a notebook, display a returned figure or call its .show() method.

Model specification and estimation

Statsmodels uses regression with ARIMA errors. For a nonseasonal model,

yt = Xt′β + ut,   ϕ(L)(1 − L)dut = θ(L)εt,

where Xt includes supplied external regressors and deterministic trend terms, ϕ(L) = 1 − ϕ1L − ⋯ − ϕpLp and θ(L) = 1 + θ1L + ⋯ + θqLq. Innovations have zero mean and variance σ2. Pass the response and regressors on their modeled scale; do not manually difference them before fitting a model that already specifies d.

trend=None inherits Statsmodels defaults: a constant for d = D = 0 and no trend with integration. Here D denotes seasonal differencing, when present. For a stationary model without other regressors, trend="c" estimates its unconditional mean μ. In an AR(1) equation the corresponding intercept is (1 − ϕ1)μ, not μ. trend="t" adds a linear deterministic time path; trend="ct" adds both a constant and a linear path. With d = 1, a linear level trend represents drift (a constant after differencing), while a level constant is eliminated by differencing and is not allowed by Statsmodels. More generally, trend powers below d + D are not permitted. trend="n" supplies no deterministic trend. External controls retain their regression interpretation conditional on the ARIMA error specification; built-in trends are supplied by Statsmodels.

Parameter inference

Fit models with Statsmodels ARIMA(...).fit(). at.coefficient_diagnostics() returns estimates, standard errors, z-statistics, asymptotic p-values, and confidence intervals (confidence=0.95). at.parameter_correlation() returns the estimated parameter correlation matrix; include_variance=True includes sigma2. at.joint_significance() takes parameter names and returns a joint Wald test against zero.

coefficients = at.coefficient_diagnostics(result)
correlations = at.parameter_correlation(result, include_variance=True)
joint_test = at.joint_significance(result, parameters=["ar.L1", "ma.L1"])
print(coefficients.round(4))

In the seeded example, the fitted AR and MA coefficients are approximately 0.728 and 0.418, close to the generating values 0.7 and 0.4. Sampling variation means equality is not expected; the reported intervals quantify approximate coefficient uncertainty conditional on this specification. Small displayed p-values are rounded values, not probabilities exactly equal to zero.

confidence must lie strictly between zero and one. Consult result.param_names when specifying joint restrictions. These functions report inference rather than automatic significance classifications.

The joint test has null H0 : βS = 0 for the selected parameter vector and uses $W=\hat\beta_S'\widehat{\operatorname{Var}}(\hat\beta_S)^{-1}\hat\beta_S$. Under regularity conditions its reference distribution is asymptotically χ2 with one degree of freedom per independent restriction. A rejection concerns the joint restriction, not the importance of every coefficient. Coefficient z tests and intervals are also asymptotic and depend on the fitted covariance estimate. Large estimated parameter correlations can signal imprecise individual estimates or overparameterization; they are not a selection rule.

Model diagnostics

Parameters and model structure

at.root_diagnostics() tabulates AR/MA roots, moduli, and inverses. at.is_causal() and at.is_invertible() return booleans; at.root_summary() combines the root checks in a Series. Causality refers to the stationary AR component, not the level stationarity of an integrated series.

at.common_roots() reports AR–MA pairs within inverse-root distance tol=0.05; exact_tol=1e-10 distinguishes numerically common from near-common pairs. at.plot_inverse_roots() returns their interactive plot with the unit circle.

With the polynomial signs defined above, causality requires AR roots outside the unit circle; invertibility requires MA roots outside it. Equivalently their inverse roots lie inside. Boolean checks use a numerical margin of 1e-10 by default. Near-common AR/MA roots suggest possible cancellation and redundant parameters, with proximity measured between inverse roots in the complex plane. These numerical root checks do not establish overall model adequacy.

roots = at.root_diagnostics(result)
causal = at.is_causal(result)
invertible = at.is_invertible(result)
common = at.common_roots(result)
root_checks = at.root_summary(result)
root_plot = at.plot_inverse_roots(result)

Residual behavior

at.ljung_box_test() requires a lag or sequence of lags greater than the ordinary plus seasonal AR/MA coefficient count, and reports adjusted degrees of freedom and p-values. at.residual_correlations() returns residual ACF/PACF values and approximate individual white-noise bounds; these bounds are not a joint test. Its maximum lag is floor(T / 2), where T is the usable residual sample size.

at.jarque_bera_test() returns the normality statistic, p-value, skewness, and conventional kurtosis. at.plot_residual_diagnostics() combines residuals, ACF, PACF, and valid-lag Ljung–Box p-values in a four-panel figure.

ljung_box = at.ljung_box_test(result, lags=[5, 10, 20])
residual_acf_pacf = at.residual_correlations(result, lags=20)
normality = at.jarque_bera_test(result)
residual_plot = at.plot_residual_diagnostics(result, lags=20)

Residual diagnostics exclude initialization periods (the maximum of likelihood burn-in and diffuse periods) and unobserved responses. Lag diagnostics reject interior gaps rather than joining observations across them. Jarque–Bera uses the remaining finite residuals; its displayed skewness and conventional kurtosis reproduce the statistic.

Ljung–Box rejection indicates evidence of remaining serial correlation through the requested lag. Non-rejection means insufficient evidence against that null, not proof of white noise or model adequacy. Jarque–Bera instead assesses marginal normality: normal residuals can still be autocorrelated, and uncorrelated residuals need not be normal. Its reference distribution is asymptotic chi-squared with two degrees of freedom. Inspect residual plots, sample size and specification alongside p-values rather than treating one threshold as a specification rule.

Innovation dynamics

at.dynamic_effects() returns Statsmodels responses of the modeled dependent variable to a one-unit innovation, and their cumulative sums, from horizon zero through horizon=20. at.plot_dynamic_effects() plots both. Responses incorporate the fitted integration structure. A random walk has a unit response at every horizon; summing these gives 1, 2, 3, … rather than reconstructing its levels from stationary responses. An innovation response is not an intervention regression contribution or, without additional assumptions, an economic causal effect.

effects = at.dynamic_effects(result, horizon=12)
effects_plot = at.plot_dynamic_effects(result, horizon=12)

Model comparison and selection

Selection requires identical ordered response values, missing positions and time indexes, effective sample size and initialization metadata. Supply d= when a table contains more than one differencing order. Search output is grouped by d. N and parameter counts follow Statsmodels nobs_effective and df_model, including concentrated scale and exact diffuse terms; numerical equality with R is not assumed. Rebuild older tables without sample identity metadata.

Choose the integration order from the substantive model, time-series evidence and appropriate differencing analysis before comparing ARMA orders. Displaying criteria for several d values is allowed, but these fits need not share the same likelihood basis. select_model(table, d=1) restricts the candidate set to d = 1; it does not choose d by minimizing criteria across integration orders. order_search() performs no differencing tests. With d=None, auto_arima() uses StatsForecast’s separate unit-root/differencing procedure before its ARMA search; it is a benchmark rather than a replacement for that specification work.

Information criteria

Writing ℓ for the reported fitted log likelihood, N for effective observations and k for Statsmodels df_model,

$$ \begin{aligned} \mathrm{AIC}&=-2\ell+2k,\\ \mathrm{AICc}&=\mathrm{AIC}+\frac{2k(k+1)}{N-k-1},\\ \mathrm{BIC}&=-2\ell+k\log N,\\ \mathrm{HQIC}&=-2\ell+2k\log(\log N). \end{aligned} $$

AICc is undefined when N − k − 1 ≤ 0 and is reported as missing; nonfinite criterion values are ineligible. Counts include free parameters, concentrated innovation scale and exact diffuse state terms where applicable. Effective N follows the likelihood burn-in convention and should not be read as a generic count of nonmissing observations. Lower values balance fit against complexity only among eligible comparable candidates. They do not certify adequacy or causality. Recognized non-optimizer fits may be reported and selected, but this does not make their estimates maximum likelihood or establish the usual IC interpretation for an arbitrary estimator.

Initialization and convergence safeguards

compare_models() reports candidates without rejecting incompatible samples or initializations; select_model() enforces comparability. The comparison table includes Initialization, Initialization Status, Initialization Detail and Convergence Status. Unsupported or unavailable initialization metadata prevents selection; rebuild older tables lacking these safeguards.

Signatures distinguish stationary, approximate-diffuse and exact-diffuse initialization. They retain diffuse means, approximate-diffuse variance and its units. Burn-in, diffuse periods and differencing must also agree. Stationary state dimensions and their model-dependent covariances need not be identical, so ordinary ARIMA specifications with different state-space sizes remain comparable. Known/custom state priors and unsupported representations have no automatic equivalence rule and are conservatively excluded from selection. Concentrated filtering scales approximate-diffuse variance by innovation scale; its variance convention cannot be mixed with absolute diffuse variance. Stationary and compatible exact-diffuse fits may mix concentrated and explicit scale estimation. Numerical equality with R is not assumed.

Convergence uses state-space mle_retvals and fit_details.minimize_results.success where applicable, including GLS inner optimizers. Any explicit failure excludes the fit; unknown required convergence also excludes it. Converged=None distinguishes absent optimizer evidence from success, with Convergence Status separating unknown evidence from recognized non-optimizer estimators (Yule-Walker, Burg, innovations, Hannan-Rissanen). The latter remain eligible, but a not-applicable optimizer status does not imply maximum-likelihood estimation or model adequacy.

Grid and recursive estimation retain warnings even when a fit raises an exception, alongside the failure message.

at.compare_models() accepts at least two fitted models and optional distinct names. Its table includes likelihood, AIC, AICc, BIC, and HQIC. Compare models for the same dependent variable and sample.

at.order_search() searches nonseasonal orders from zero to p_max/q_max, and differencing orders from d_min through d_max (both default to zero). criterion sorts the table; convergence status is retained. at.select_model() returns the eligible row minimizing AIC, AICc, BIC, or HQIC, excluding non-converged models when that column is present. Selection is not a diagnostic assessment.

alternative = ARIMA(y, order=(1, 0, 0), trend="n").fit()
comparison = at.compare_models(result, alternative, names=["ARMA(1,1)", "AR(1)"])
search = at.order_search(y, p_max=2, q_max=2, criterion="BIC", trend="n")
selected = at.select_model(search, criterion="BIC")
print(selected)

at.auto_arima() returns a fitted StatsForecast AutoARIMA object, not a Statsmodels result. This nonseasonal benchmark accepts AIC, AICc, or BIC. With d=None, AutoARIMA chooses differencing; allow_mean and allow_drift control deterministic components. at.auto_arima_summary() takes that fitted object and returns a compact Series, including its mean/drift interpretation. The package’s Statsmodels diagnostic/forecast functions do not accept this object directly.

automatic = at.auto_arima(y, criterion="BIC", max_p=2, max_q=2)
automatic_summary = at.auto_arima_summary(automatic)

Forecasting

All four functions below accept a fitted Statsmodels ARIMA result. steps=20 is a positive integer, and level=0.95 is a central normal-theory prediction-interval coverage strictly between zero and one.

  • at.forecast_error_variance() returns a NumPy array for horizons 1 through steps. It independently calculates innovation-based variance from the full ARIMA psi weights, including ordinary/seasonal integration, on the original dependent-variable scale.
  • at.dynamic_forecast() returns a DataFrame indexed by Horizon, with Forecast, FEV, SE, Lower, and Upper. Forecasts are recursive from the sample end; uncertainty comes from the independent FEV calculation.
  • at.plot_forecast() returns an observed/forecast figure with two unfilled interval boundary lines and a forecast-origin marker.
  • at.plot_fan_chart() returns a figure with nested shaded central intervals, stronger centrally and fading outward, and a clear point forecast.
fev = at.forecast_error_variance(result, steps=20)
forecast = at.dynamic_forecast(result, steps=20, level=0.95)
forecast_plot = at.plot_forecast(result, steps=20, level=0.95, history=50)
fan_plot = at.plot_fan_chart(result, steps=20, history=50)
print(forecast.head().round(4))

For this seeded ARMA fit, the first forecast is about 2.94, with a 95% prediction interval of approximately [0.97, 4.91]. At horizon two, variance increases from about 1.01 to 2.34. The point forecast moves toward the fitted zero mean while uncertainty accumulates; these intervals concern future observations conditional on the fitted model, not certainty about its specification. Small numerical differences across dependency versions are expected.

The default fan levels are exactly (0.50, 0.70, 0.80, 0.90, 0.95, 0.99). Custom levels must be nonempty, distinct, and strictly between zero and one; input order does not matter. In both plots, history=50 shows the final 50 observations, history=None shows the entire sample, and a larger request shows all available observations. Positive integer histories are required otherwise. Supported time indices continue into the forecast; period indices display period-start dates. Unsupported indices use observation positions if Statsmodels can produce the forecast; its forecasting errors propagate.

custom_fan = at.plot_fan_chart(result, steps=12, levels=(0.95, 0.50, 0.80), history=None)

For innovation weights ψj of the full fitted ARIMA transfer function, including integration, the implemented variance at horizon h ≥ 1 is

$$ V_h=\hat\sigma^2\sum_{j=0}^{h-1}\psi_j^2,\qquad \hat y_{T+h\mid T}\ \pm\ z_{(1+\mathrm{level})/2}\sqrt{V_h}. $$

For an AR(1), ψj = ϕj, so variance approaches a finite limit when |ϕ| < 1. For a random walk, ψj = 1 and Vh = hσ̂2: uncertainty grows with the horizon. These are conditional normal-theory prediction intervals given the estimated specification, parameters and future regressor paths. Their nominal coverage depends on the model and innovation assumptions; they are not confidence intervals for the conditional mean alone. Dynamic forecasts recurse from the sample endpoint without inserting subsequently observed outcomes. Static forecasting and forecast evaluation/comparison belong to Forecasting-Tools.

FEV treats fitted parameters and past innovations as known; finite-sample state uncertainty or missing observations can cause differences from Statsmodels’ state-space variances. Parameter-estimation uncertainty is not included. Concentrated-scale fits use result.scale; other fits use the sigma2 parameter. Models with external regressors require future values through keyword-only exog=. No transformations or evaluation procedures are added by these functions.

Manual intervention modelling

Interventions describe specified events; no dates or decay rates are detected or estimated automatically. at.outlier_regressors(y, dates=None, types="AO", delta=0.7, *, positions=None) returns a named pandas DataFrame ready for Statsmodels ARIMA(..., exog=X).fit().

For a chosen observation T0:

Type Regressor Coefficient interpretation
AO One at T0, zero elsewhere One-observation displacement
LS Zero before T0, one from T0 onward Sustained level displacement
TC Zero before T0, delta**(t-T0) afterward Initial displacement, decaying by delta per observation

The default TC decay is 0.7, following ARIMA-Tools-R; require 0 < delta < 1. One scalar decay applies to all TC events. Multiple interventions and repeated types are allowed; duplicate type/date pairs are rejected. Different types on the same date are allowed, but can be unidentified in short samples.

Complete Statsmodels example

The following simulated example specifies a permanent shift, a one-quarter outlier, and a temporary change. In empirical work, choose dates from the substantive question and inspect the fitted diagnostics.

import numpy as np
import pandas as pd
from statsmodels.tsa.arima.model import ARIMA
import arima_tools as at

index = pd.period_range("2000Q1", periods=104, freq="Q")
X = at.outlier_regressors(
    index, dates=["2008Q4", "2020Q2", "2021Q1"],
    types=["LS", "AO", "TC"], delta=0.7,
)
rng = np.random.default_rng(1234)
y = pd.Series(
    100 + 0.2 * np.arange(len(index))
    + X.to_numpy() @ np.array([5.0, -8.0, 3.0])
    + rng.normal(size=len(index)),
    index=index, name="Output",
)
results = ARIMA(y, order=(1, 0, 0), trend="ct", exog=X).fit(
    cov_type="oim", method_kwargs={"maxiter": 500},
)
print("Converged:", results.mle_retvals["converged"])
print(at.coefficient_diagnostics(results))
effects = at.intervention_effects(results, X)
figure = at.plot_interventions(y, X, results=results, individual=True)
future_X = at.extend_interventions(X, steps=8)
forecast = at.dynamic_forecast(results, steps=8, exog=future_X)
fan = at.plot_fan_chart(results, steps=8, exog=future_X)

The example explicitly requests observed-information covariance (`cov_type=“oim”) and allows more optimizer iterations. Inspect convergence and standard errors: sparse, single-observation AO regressors can give unstable default OPG covariance estimates. An AO coefficient is supported by very limited event information; normal/Wald inference remains approximate and should not determine event inclusion automatically. The package does not change Statsmodels fitting defaults.

Dates, positions and metadata

Pass a Series, pandas Index, or one-dimensional array. Exactly one of dates or positions is required. Positions are zero-based; arrays receive a RangeIndex. Period dates resolve to their containing period using the index frequency. Datetime events require exact, complete dates with matching timezone. Calendar indexes must be regular, unique and increasing, without missing labels. Numerical indexes must be unique and increasing. No observation is sorted or dropped; missing response values retain their positions. TC decay advances one observation at a time, rather than by calendar-day distance.

Generated columns include names such as AO_2020Q2, LS_2008-09, and TC_pos12. X.attrs["arima_tools_interventions"] is a version-1 dictionary with:

  • origin_length, origin_index: original sample length and index description.
  • row_start, index: current block’s offset and index description.
  • events: type, zero-based position, label, column, and delta (None for AO/LS).

Descriptions contain index kind, dtype, frequency, timezone and ordered labels. extend_interventions preserves the original event specifications while updating the current block. Keep the original X: pandas transformations may discard attrs. Effects, plotting and extension validate metadata against the numerical columns; interventions are never inferred from prefixes alone. Ordinary controls can be combined with X for fitting; pass the original intervention-only X to the effects and plotting functions.

Effects, adjustment and identification

at.intervention_effects(results, X) returns an indexed DataFrame: Observed, one named contribution per intervention, Combined, and Adjusted. Each contribution is beta_hat*X; Combined sums only those intervention contributions. Adjusted is Observed minus Combined. Ordinary controls, deterministic terms and ARIMA errors are not removed. The intervention-adjusted series is not a residual. Plotting delegates to this same numerical helper.

at.plot_interventions(y, X, *, results=None, individual=False, title="Intervention Effects") returns a Plotly Figure. Without results it shows observations and chosen dates. With results, the upper panel shows observed and adjusted series; the lower panel shows the combined effect. individual=True adds component curves. Same-date events share one marker and tooltip.

All effects stay on the modeled response scale. If y is log GDP, adjustment remains in logarithms. Statsmodels estimates a regression with ARIMA errors: pass the undifferenced regression columns even when d > 0. An LS remains a step in the supplied response; its first difference is a pulse. An AO’s first difference has adjacent positive and negative pulses. TC remains geometric on the supplied scale. ARIMA integration does not turn these regressors into innovation impulse responses. There is no automatic back-transformation.

Deterministic and stochastic permanence are different. In yt = ωLSt + ut, with ut = ut − 1 + εt, the specified LS contributes a permanent deterministic shift of magnitude ω. An innovation εt also has a permanent effect on the stochastic component ut. A lasting movement in the observed series alone therefore does not establish that it is deterministic or caused by the specified event. The estimated LS coefficient describes the shift conditional on the chosen event, controls and ARIMA error model.

order_search(..., exog=None) and recursive_estimation(..., exog=None) accept keyword-only finite aligned regressors. DataFrame indexes must match Series y exactly; arrays align by position, with indexed exog supplying labels when y is an array. All external columns and built-in trends enter identification checks, but the original columns are passed to Statsmodels. Complete response samples retain the differenced-design check. With missing responses, the check preserves the original time grid and tests observed regressors modulo the visible integration directions: constants for I(1), affine paths for I(2). Thus a contrast across a gap can identify an LS even when its event-date response is missing. Rank uses column scaling and machine-precision SVD tolerance, not a discretionary near-collinearity cutoff. This algebraic check does not guarantee precise estimates.

An LS at the first observation can duplicate a constant or disappear under differencing. Events at the last observation can generate identical columns. The builder warns about dependent event columns; fitting helpers report failed or unidentified specifications without removing regressors. Recursive windows before an event is observed retain missing estimates and an explanatory status. Parameter counts include external coefficients. Stage 2 convergence, effective sample, initialization and differencing safeguards remain in force. Comparison reports Identified and Identification Status; selection requires identification to be established (Identified=True). Different exogenous specifications remain comparable when their response sample and likelihood conventions are compatible; X equality is not required.

For response gaps, the observed-data check recognizes the standard Statsmodels state-space representation with proper stationary ARMA states and integration-only exact-diffuse initialization (no burn-in), or approximate-diffuse initialization with its standard integration-order burn-in. Unsupported initialization, additional diffuse states or custom burn-in produce identification not established, rather than a mathematical rejection. Exact dependencies among observed regression columns remain unidentified. Under exact diffuse initialization, confounding with the integration directions is also unidentified. Under finite approximate-diffuse initialization, deficient diffuse-limit contrasts are inconclusive: the finite initial-state prior can supply additional likelihood information. Successful optimization alone does not resolve this uncertainty.

Search may estimate an inconclusive specification, retaining Identified=None, an explanatory status and a warning; automatic selection excludes it. Effects from an inconclusive supplied fit carry a warning and remain conditional on its coefficients. Neither helper removes columns or responses. Recursive estimation retains its existing requirement for a complete finite response sample; its complete-data rank check continues to report collinear post-event windows until the full design becomes identifiable.

Dynamic forecasting with interventions

at.extend_interventions(X, steps=20, *, future_index=None) returns future rows only. AO stays zero, LS stays one, and TC decay continues from the original event, without restarting at the forecast origin. It continues existing events; it does not introduce new future events. Regular period, datetime, RangeIndex and equally spaced numerical indexes can continue automatically; otherwise supply an increasing future index. Explicit continuations must match known frequencies.

dynamic_forecast, plot_forecast and plot_fan_chart accept keyword-only exog=None for all future external regressors. DataFrame columns must have the fitted names in the fitted order and match the model’s forecast index; unnamed arrays must have the correct shape and are interpreted in fitted column order. Supply ordinary controls too, when present; built-in trends need no supplied columns. Forecast-error variances are unchanged and condition on the parameters and future regressors. No coefficient, date, decay or model-selection uncertainty is added. Existing missing-history/initialization limitations of innovation-based FEV still apply. Static forecasting and forecast evaluation remain the responsibility of Forecasting-Tools.

Recursive estimation and parameter stability

at.recursive_estimation() takes the original series and a (p, d, q) order and returns a long-format expanding-window table with estimates, standard errors, intervals, endpoints and convergence status. initial is an observation count, a fraction between zero and one, or None (an automatic 10% rule subject to min_df=20). Ordinary controls and interventions can be supplied through aligned keyword-only exog=. The response must be complete and finite. Windows retain the same specified columns; unidentified windows remain visible with missing estimates and explanatory status rather than silently dropping regressors.

The intervention example above defines a separate results object. This stability example returns to the earlier ARMA series saved as arma_y:

recursive = at.recursive_estimation(arma_y, order=(1, 0, 1), initial=220, trend="n")
stability_plot = at.plot_parameter_stability(recursive, parameters=["ar.L1", "ma.L1"])

at.plot_parameter_stability() takes the recursive table. parameters=None displays all parameters except sigma2; a string or sequence selects parameters. reference=True adds full-sample estimates only when the final window is valid. Captured warnings and failure reasons remain in the table; nonconverged estimates are excluded from the plot. An optional breakpoint is only a graphical marker matching the endpoint index, not a structural-break test.

Intervals are pointwise, approximate normal intervals, estimate plus/minus the normal critical value times its standard error. Expanding windows overlap, so successive estimates are dependent; these are not simultaneous confidence bands. A changing path can motivate investigation but is not a formal rejection of parameter constancy. A visually stable path does not establish constancy either.

Exact public signatures and principal returns are listed below. results and result are the parameter names actually used by the API; both denote a fitted Statsmodels result unless otherwise specified above. Tests and execution scope

From the repository root in the activated environment, run python -m unittest discover -s tests -v. The examples use simulated data and require no downloaded datasets. Figures are returned rather than automatically displayed; in Jupyter display the figure or call .show().

The examples were checked in an existing environment with Python 3.14.7, Statsmodels 0.15.0 and StatsForecast 2.1.1. The standalone HTML build was checked with Quarto 1.10.19. These are tested versions, not additional dependency pins.

The earlier source-checkout workflow passed clean-environment and hosted Colab checks for estimation, diagnostics, dynamic forecasting and Plotly display. Those results do not establish installation from the new GitHub pip reference. Version 1.0.1 adds setuptools packaging; the tag is reserved for final release approval. See the README installation section for the target student commands and release status. Dependency versions may change in future runtimes.

Rebuilding the HTML

The examples are ordinary Python code blocks: execute them separately in a fresh session; rendering does not run them. With Quarto installed separately from the Python environment, the standalone build command from the repository root is:

quarto pandoc docs/ARIMA_Tools_Documentation.qmd \
  --from markdown --to html5 --standalone --toc --toc-depth=2 \
  --embed-resources --mathml --syntax-highlighting=none -o docs/index.html

--mathml renders equations as native MathML in a modern browser without an external mathematics script.
